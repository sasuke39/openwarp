# 架构、执行与安全边界

## 运行拓扑

```text
Windows x64 OpenWarp UI
  ├─ 内置 Agent → 本机 Go Adapter → Native / Pi / DSH → 模型服务
  │                       ↓ 工具请求与结果
  ├─ Managed SSH 执行器 → 独立 ssh.exe 执行 → Linux 命令/受管后台任务
  ├─ SSH 终端宿主 → 交互 ssh.exe → Linux Shell / Warpify
  └─ 上传执行器 → sftp.exe → 当前 SSH 服务器的远端目录
UU：仅连接开发者与测试电脑，不参与上述产品运行链路
```

## 平台能力与上下文

- 复用现有平台和执行上下文结构；补充 SSH-only 能力判断，不新增平行协议。
- Windows 首版隐藏本地终端、项目 Agent 入口，空白页引导添加 SSH 服务器。
- 后端同样拒绝本地工作区工具调用；仅隐藏按钮不构成限制。
- 工具路由携带 conversation、turn、tool_call 与稳定 server/profile 标识。
- 明确区分 Windows 宿主平台与 Linux 工具执行平台；给模型的工作目录必须是远端目录。
- 切换服务器不得把旧工具结果送入新上下文；重连后核验目标身份与目录。
- 上传读取指定本地文件是允许的传输操作，不等于开放本地 Agent 文件访问。

## SSH 启动与认证

- 优先参数化启动受信路径的 ssh.exe/sftp.exe；环境变量用进程 API 设置。
- 禁止依赖本地 Bash 解释 `KEY=value ssh ...`，禁止用 PowerShell 再包一层字符串。
- 复用现有 Windows PTY/终端宿主；“不提供本地终端”不代表删除宿主 PTY。
- 远端 Shell 字符串仍按 Linux 规则构造；本地 Windows 参数与远端转义分别处理。
- 密码通过系统凭据存储与原生 askpass 辅助程序读取；复用现有 secure_storage 抽象。
- 检查 Windows OpenSSH 的 askpass 实际行为；不支持时明确失败或交互认证，不泄露密码。
- 私钥、加密私钥、ssh-agent、首次 host key 确认与变更拒绝分别验证。
- 不继承自动回答 yes 的主机信任行为；密码、验证码不写命令行、日志或测试产物。

## 命令与生命周期

- foreground：等待退出并回传 stdout/stderr/exit；不因超过几秒升级为后台任务。
- background：模型显式选择，创建独立受管执行任务，返回 job_id 后可读、写、取消。
- 独立任务不占住用户交互终端；一次新 ssh.exe 不等于必须复用同一 TCP 连接。
- 运行超时必须返回明确失败，禁止伪报成功、后台启动或仅杀本地连接就宣称远端已停。
- Stop 复用现有取消状态机，分别处理模型流、审批、等待结果、本地进程与远端任务。
- 后台任务的保留/终止策略沿用已确认业务契约并在 UI 说明；断网时不能保证远端终止。
- 每个工具请求有唯一终态；迟到、重复结果隔离；取消完成后同一会话允许新 Turn。
- 默认新输入排队；点 Steer 后在下一次安全 exchange 注入，展示接受/应用状态。
- 工具 reject 作为工具结果回传，不破坏整个会话。

## UI 与失败行为

- Warpify 握手成功后使用现有 Block；失败显示明确原因和 Agent/PTY 半屏降级视图。
- 不把“SSH 已连接”或“tmux 已安装”当作 Warpify 成功。
- 上传目标锁定为发起时的服务器与远端目录，显示进度、失败和重试入口。
- 未知远端目录要求用户选择，不猜测本地目录；覆盖已有文件需要明确处理。
- Adapter/Harness 异常退出：本轮标失败或中断、清理等待、保留历史，不复活悬空工具。
- 如 Windows 难以维护某项能力，报告阻塞；不得通过禁用失败测试宣称兼容。
