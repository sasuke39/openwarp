# 02-工具定义与协议

## 工具名

`update_task_list`（不用 `todo_write`，避免和 Claude Code 混淆，也避免模型从训练数据里带偏见）

## JSON Schema

```json
{
  "type": "object",
  "properties": {
    "tasks": {
      "type": "array",
      "description": "Complete task list, replacing any previous list. Each task must have a unique id.",
      "items": {
        "type": "object",
        "properties": {
          "id": {
            "type": "string",
            "description": "Unique task identifier (e.g. 'step-1', 'build', 'test')"
          },
          "content": {
            "type": "string",
            "description": "What this task does, one sentence"
          },
          "status": {
            "type": "string",
            "enum": ["pending", "in_progress", "completed", "cancelled"],
            "description": "pending=not started, in_progress=currently working on, completed=done, cancelled=abandoned"
          },
          "priority": {
            "type": "string",
            "enum": ["high", "medium", "low"],
            "description": "high=must do, medium=should do, low=nice to have"
          }
        },
        "required": ["id", "content", "status"]
      }
    }
  },
  "required": ["tasks"]
}
```

## 校验规则（adapter 侧强制执行）

调用时按顺序校验，任一失败则返回错误（不更新状态）:

1. **id 唯一**：所有 task 的 id 不能重复
2. **单 in_progress**：最多一个 status=in_progress
3. **id 非空且不超过 50 字符**
4. **content 非空且不超过 200 字符**
5. **合法状态**：只允许 pending/in_progress/completed/cancelled

错误返回格式：

```json
{"error": "validation failed: multiple in_progress tasks (step-2, step-3). Only one task can be in_progress at a time."}
```

## 成功返回值

```json
{
  "ok": true,
  "active_task": "step-2: implement the C renderer",
  "completed": 1,
  "pending": 2,
  "total": 3
}
```

## 覆盖语义（关键设计）

**每次调用是全量替换，不是增量追加。** 模型每次调 `update_task_list` 都传完整的任务列表，服务端直接替换当前状态。

理由（对齐 Claude Code):
- 简单、无歧义，模型不需要学"追加/删除/更新"三种操作
- 模型可以重构计划（删掉过时的、加新的、改优先级）
- 状态一致性由模型负责，adapter 只做校验

## 工具声明里的描述（给 LLM 看的）

```
update_task_list - Update the task list for this work session. Use this to plan
your approach, track progress, and stay focused. Call it:
- At the start of any non-trivial task to outline your steps
- After completing each step to mark it done and move to the next
- When you realize your plan needs to change

Rules:
- Only one task can be in_progress at a time
- Always pass the complete list (replaces previous state)
- Keep tasks concrete and actionable
- When all tasks are completed, you may finish your response
```
