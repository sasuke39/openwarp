# 交互模型

## 输入状态

输入框只显示三种用户可理解状态：

| 状态 | 含义 | Enter 行为 |
|---|---|---|
| 自动 · 终端命令 | 已识别为 Shell | 在当前终端/SSH 执行 |
| 自动 · Agent 指令 | 已识别为自然语言 | 按 Turn 状态提交或排队 |
| 手动 · 终端/Agent | 用户覆盖识别 | 严格按选择执行 |

状态必须同时使用图标和文字，不能只靠颜色。模式切换只影响当前草稿；清空后恢复自动识别。

## Agent Prompt 提交

| Turn 状态 | 默认行为 |
|---|---|
| IDLE/COMPLETED/FAILED/CANCELLED | 在同一 Conversation 新建 Turn |
| RUNNING/AWAITING_TOOL | 新增 Queued Prompt |
| CANCELLING | 保留队列，等回到 IDLE 再提交 |

Queued Prompt 显示原文、排队状态、删除和“插入当前 Turn”。点击插入后依次显示“正在提交引导”“已接受”“已应用”或“失败”，记录保留在时间线。

## 终端命令提交

- 无论 Agent 是否正在运行，命令都走终端执行路径，不进入 LLM。
- 命令产生普通 Warp Block，保留命令、输出、退出码和耗时。
- 不取消、不 Steer、不改变当前 Turn；并发效果等价于用户另开一个终端操作。
- 命令 Block 与 Agent 内容按实际发生顺序显示，但保持各自样式。

## 自动识别优先级

1. 用户手动选择或显式前缀。
2. 已解析的 Shell 结构、历史命令、别名和可执行首词。
3. Slash/Skill/附件等明确 Agent 语法。
4. 自然语言分类器。

不能采用“包含中文就一定是 Agent”。`ls 中文目录`、`cat 配置.yaml` 必须优先识别为命令。分类结果带输入版本号，过期异步结果不得覆盖新文本。

## SSH 展示

- Warpify 成功：命令是结构化 Block，与本地终端一致。
- Warpify 失败：上方 Agent 时间线、下方原始 PTY，并提示当前为兼容模式。
- 兼容模式不伪造 Block；输入终端命令时焦点和结果落入下方 PTY。
